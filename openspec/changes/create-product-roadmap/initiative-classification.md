# Initiative Classification — Create Product Roadmap

## Outcome and boundary

Task 3.2 assigns immutable `RM-###` identities and lifecycle metadata to the Phase 3.1 reconciled initiative set. This is a review artifact, not the canonical roadmap: it does **not** rank initiatives, assign `Now`, commit implementation, publish `docs/product/roadmap.md`, create Git–Notion fields, or create/populate Notion.

## Classification rules

- IDs are sequential and apply to reconciled initiatives, never directly to merged source candidates. C-04/C-05 are preserved under RM-005; C-23 is preserved under RM-006.
- `shipped`/`Shipped` is reserved for the four approved shipped baselines. It records a bounded baseline, not universal workflow completion.
- `unfinished`/`Later` records accepted open work without ordering or delivery commitment. `idea`/`Explore` records exploratory or decision-gate work. `deferred`/`Explore` records an accepted future capability with unresolved external decisions. `deferred`/`Future-only` is reserved for C-18.
- Completion evidence is evidence of the stated baseline or an explicit statement that no completion evidence exists. It never treats technical presence as proof of a stable end-to-end outcome.
- Every `2026-08-24` decision below records metadata classification only; it does not supersede preserved source provenance, checkpoint disposition, or merge history.
